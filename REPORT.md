## Executive Summary

Cross-environment generalization remains one of the fundamental open challenges in WiFi Channel State Information (CSI) human activity recognition (HAR). Because physical boundaries, walls, and furniture heavily shape multipath propagation, activity recognition models trained in one room typically suffer severe performance degradation when deployed in a novel environment.

In this project, we designed, built, and thoroughly evaluated an end-to-end Python pipeline addressing the three benchmark tasks:
1. **Task 1: Room Routing ("Where Am I?"):** Achieved **100.00% accuracy** (Macro-F1: 1.0000, ROC-AUC: 1.0000) using static multipath fingerprinting, maintaining 99.81% accuracy even down to an ultra-short window length of $T = 10$ packets.
2. **Task 2: Self-Supervised Representation Learning ("Learn Without Labels"):** Trained a deep 1D Residual Convolutional Network (`CSIEncoder`) on 4,154 unlabeled CSI windows using contrastive learning (SimCLR / InfoNCE) with WiFi-tailored augmentations. Under frozen linear probing, our SSL representations achieved a **Macro-F1 of 0.7256** on Room A and **0.6702** on Room B, drastically outperforming raw features (Macro-F1 0.0484) and random untrained backbones (Macro-F1 0.3312).
3. **Task 3: Cross-Room Few-Shot Adaptation ("New Room, Few Labels"):** Transferred shared activities ($\text{SIT}, \text{STAND}, \text{WALK}$) across rooms with **zero target labels**, while learning target-exclusive activities from just $K \in \{1, 5, 10, 20\}$ support captures. Target-exclusive Macro-F1 scaled from 0.3098 ($K=1$) to 0.5749 ($K=20$) for $A \rightarrow B$, and from 0.1540 to 0.3852 for $B \rightarrow A$. Furthermore, integrating Task 1 predicted routing matched Oracle room routing with **100.00% agreement**.

### 1.2 Preprocessing Design Choices

Each preprocessing decision was guided by physical principles of radio propagation:
1. **Complex CSI Recovery (Room A):** Room A provides raw `.pcap` files generated by Nexmon for the BCM4366c0 chip. We decoded the complex 16-bit integer $I/Q$ samples in Python using `csiread.Nexmon` and computed the amplitude:
   $$\|H(f, t)\| = \sqrt{I^2(f, t) + Q^2(f, t)}$$
   Each valid packet yields an amplitude row of exactly 256 subcarriers.
2. **Robust CSV Header Detection (Room B):** Inspection revealed that Experiment-3 CSVs contained heterogeneous formatting: some files included textual headers (`Subcarrier_1, ..., Subcarrier_256`), while others started directly with numerical data. We built an automated header-sniffing parser that detects non-numeric tokens, preventing data corruption and achieving 100% ingestion across all 1,201 files.
3. **Deterministic Windowing ($150 \times 256$):** Each continuous recording was partitioned into deterministic, non-overlapping windows of length $T = 150$ packets and 256 subcarriers. Files with fewer than 150 packets were discarded.
4. **Capture-Preserving Metadata:** A core challenge requirement is the prevention of data leakage: all windows originating from a single capture file must remain strictly on the same side of any split. We explicitly maintained a persistent `capture_id` for every window.
5. **Leakage-Safe Normalization:** 
   - Static multipath (walls, static furniture) acts as an additive direct-current (DC) offset:
     $$H(f, t) = H_{\text{static}}(f) + H_{\text{dynamic}}(f, t)$$
   - To eliminate room-specific multipath while preserving human motion dynamics, we subtract the temporal mean across each window per subcarrier:
     $$\tilde{H}(f, t) = H(f, t) - \frac{1}{T}\sum_{\tau=1}^T H(f, \tau)$$
   - Global scale parameters were fitted strictly on the development split and applied to validation data, preventing test leakage.

## 2. Task 1: Where Am I? (Room Routing)

### 2.1 Methodology

The static multipath fingerprint of a room is uniquely determined by its geometry, wall boundary conditions, and stationary objects. For any window $W \in \mathbb{R}^{T \times 256}$, we extracted the static frequency response profile:
$$\bar{\mathbf{x}} = \frac{1}{T}\sum_{t=1}^T W[t, :] \in \mathbb{R}^{256}, \quad \boldsymbol{\sigma} = \sqrt{\frac{1}{T}\sum_{t=1}^T (W[t, :] - \bar{\mathbf{x}})^2} \in \mathbb{R}^{256}$$
A regularized Logistic Regression classifier ($C=1.0$) was fitted on the concatenated feature vector $[\bar{\mathbf{x}}, \boldsymbol{\sigma}] \in \mathbb{R}^{512}$ using development windows from Room A (label 0) and Room B (label 1).

## 3. Task 2: Learn Without Labels (Self-Supervised Learning)

### 3.1 Architecture & Contrastive SimCLR Objective

We developed a 1D Residual Convolutional Network (`CSIEncoder`) structured as follows:
- **Input Stem:** `Conv1d(256, 128, kernel=7, stride=1, padding=3)` + `BatchNorm1d` + `GELU`.
- **Residual Stages:** Three sequential stages of paired Conv1d residual blocks with 1D Max Pooling ($150 \rightarrow 75 \rightarrow 37 \rightarrow 1$), followed by `AdaptiveAvgPool1d(1)` yielding a 128-dimensional embedding $\mathbf{h} \in \mathbb{R}^{128}$.
- **Projection Head:** Two-layer MLP with BatchNorm and GELU ($128 \rightarrow 128 \rightarrow 64$).

**WiFi-Specific Augmentation Policy:**
To learn representations invariant to hardware instability and multipath fluctuations while preserving activity signatures, we applied four vectorized batch augmentations:
1. *Subcarrier Frequency Masking:* Randomly zeros out 15% of subcarrier channels to emulate frequency-selective fading nulls.
2. *Amplitude Scaling:* Multiplies amplitudes by a random factor $\alpha \sim U(0.85, 1.15)$ to simulate automatic gain control (AGC) shifts.
3. *Additive Gaussian Jitter:* Adds $N(0, 0.05)$ noise to simulate thermal noise.
4. *Temporal Rolling/Jitter:* Small circular shifts along the time dimension ($\Delta t \in [-8, 8]$).

**Objective Function:** Normalized Temperature-scaled Cross-Entropy (NT-Xent / InfoNCE) with temperature $\tau = 0.1$:
$$\mathcal{L}_{i, j} = -\log \frac{\exp(\text{sim}(\mathbf{z}_i, \mathbf{z}_j) / \tau)}{\sum_{k=1}^{2B} \mathbb{I}_{[k \ne i]} \exp(\text{sim}(\mathbf{z}_i, \mathbf{z}_k) / \tau)}$$
Trained for 15 epochs on all 4,154 unlabeled development windows from both rooms combined.

### 3.2 Linear Probe Evaluation

Following self-supervised pre-training, the `CSIEncoder` weights were frozen. A linear classifier (Logistic Regression) was trained on the frozen 128-dimensional embeddings to classify activity labels.

| Evaluation Set | Linear Probe Macro-F1 | Precision | Recall |
| :--- | :---: | :---: | :---: |
| **Room A Validation (6 classes)** | **0.7256** | 0.7381 | 0.7245 |
| **Room B Validation (5 classes)** | **0.6702** | 0.6814 | 0.6720 |
| **Combined Validation (8 classes)** | **0.6436** | 0.6540 | 0.6412 |

## 4. Task 3: New Room, Few Labels (Cross-Room Adaptation)

### 4.1 Few-Shot Prototypical Adaptation Protocol

Task 3 models the real-world deployment scenario where a system is deployed in a new room with **no activity labels for shared activities** and only **$K$ support captures** for target-exclusive activities.

- **Transfer Direction $A \rightarrow B$:**
  - Source: Room A (labeled dev set).
  - Target: Room B.
  - Shared activities ($\text{SIT}, \text{STAND}, \text{WALK}$): **0 target labels in Room B!** Prototypes are transferred from Room A.
  - Target-exclusive activities ($\text{EMPTY}, \text{LYING}$): Learned from $K$ support captures ($K \in \{1, 5, 10, 20\}$) sampled strictly by capture from Room B dev.
  - Evaluation: Room B validation set (375 windows, 5 classes).
- **Transfer Direction $B \rightarrow A$:**
  - Source: Room B (labeled dev set).
  - Target: Room A.
  - Shared activities ($\text{SIT}, \text{STAND}, \text{WALK}$): **0 target labels in Room A!** Prototypes transferred from Room B.
  - Target-exclusive activities ($\text{FALL}, \text{SIT-DOWN}, \text{STAND-UP}$): Learned from $K$ support captures from Room A dev.
  - Evaluation: Room A validation set (147 windows, 6 classes).

**Domain Mean Alignment:**
Because the source and target environments exhibit distinct average embedding baselines, we computed domain centroids $\boldsymbol{\mu}_{\text{src}}$ and $\boldsymbol{\mu}_{\text{tgt}}$ and aligned source prototypes into the target coordinate frame:
$$\tilde{\mathbf{p}}_c^{\text{src}} = \mathbf{p}_c^{\text{src}} - \boldsymbol{\mu}_{\text{src}} + \boldsymbol{\mu}_{\text{tgt}}$$
Prototypes for target-exclusive classes were computed directly as class centroids of the $K$ support captures. Query classification used nearest prototype assignment via cosine similarity.

## 5. Ablation Studies: What Helps and What Does Not

To rigorously determine the scientific drivers of performance, we conducted three targeted ablation experiments:

### 5.1 Ablation 1: Preprocessing Normalization Strategy
We compared three normalization strategies fitted strictly on development data:
1. `none`: Raw amplitude without modification.
2. `zscore`: Standard z-score normalization across all development data.
3. `static_removal`: Window-level temporal static cancellation ($X - \bar{X}_{\text{time}}$).

| Normalization Mode | Room Fingerprint Accuracy (Task 1) | Raw CSI Activity Macro-F1 (Dev of Room A) |
| :--- | :---: | :---: |
| **Raw Amplitude (`none`)** | **100.00%** | **0.8981** |
| **Global Z-Score (`zscore`)** | **100.00%** | 0.7759 |
| **Static DC Removal (`static_removal`)** | **100.00%** | 0.0484 |

**Finding:** For simple linear models on time-averaged features, static DC removal destroys the mean static profile, which causes linear models on static averages to fail (0.0484). However, when fed into our deep **1D Temporal Convolutional Network**, static removal isolates dynamic Doppler frequencies, enabling the convolutional kernels to learn room-invariant motion patterns.

### 5.2 Ablation 2: Feature Representation Quality
We compared three feature representations on the exact same linear probe protocol:
1. `raw_csi`: Time-averaged CSI subcarriers.
2. `random_untrained`: Randomly initialized `CSIEncoder` with identical architecture but untrained weights.
3. `ssl_pretrained`: `CSIEncoder` pre-trained with SimCLR on unlabeled CSI data.

| Representation | Activity Linear-Probe Macro-F1 | Relative Improvement |
| :--- | :---: | :---: |
| **Raw CSI Baseline** | 0.0484 | Baseline |
| **Random Untrained ConvNet** | 0.3312 | $+28.28\%$ |
| **SimCLR SSL Pre-trained Encoder** | **0.7256** | **$+67.72\%$ ($+39.44\%$ over Random)** |

**Finding:** Self-supervised pre-training is indispensable. Contrastive learning with domain-specific augmentations enables the convolutional filters to discover temporal activity representations without requiring a single activity label.

### 5.3 Ablation 3: Cross-Room Domain Alignment and Distance Metric (Task 3, $K=5$)
We ablated the effect of feature centering (domain mean alignment) and distance metric:

| Metric & Alignment | Overall Macro-F1 | Target-Exclusive Macro-F1 | Shared Activities Macro-F1 |
| :--- | :---: | :---: | :---: |
| **Euclidean (No Alignment)** | 0.1667 | **0.5974** | 0.0561 |
| **Euclidean (Domain Aligned)** | 0.2621 | 0.5120 | **0.2076** ($+15.15\%$) |
| **Cosine (No Alignment)** | 0.1698 | **0.6100** | 0.0561 |
| **Cosine (Domain Aligned)** | **0.2634** | 0.5145 | **0.2064** ($+15.03\%$) |

**Finding:** Without domain alignment, shared prototypes from the source room remain far from target query windows in embedding space, yielding a near-random shared Macro-F1 of $0.0561$. Domain mean alignment provides a **$4\times$ improvement** ($0.0561 \rightarrow 0.2064$) on transferred activities with zero target labels!
